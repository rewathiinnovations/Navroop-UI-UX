# Agent guide — Navroop / Open Lovable

Navroop is an invite-only admin shell around Open Lovable (Next.js App Router, React 19, Tailwind, Prisma/Postgres, Firecrawl). Brand the product as Navroop. Default theme is light. Do not revert studio/admin chrome. Generation runs in the background via `GenerationProvider`.

## Product map

Authenticated app chrome: `components/layout/Sidebar` + studio shell. Generation is backgrounded via `GenerationProvider`. One Next.js server on `:3000` — only the dedicated **dev server** agent may start/restart it, run `prisma generate`, or replace locked Next/Prisma binaries (`single-dev-server.mdc`). Coolify production is `docker-compose.yml` (`app` + `postgres`); local Postgres on host `5433` is `docker-compose.dev.yml`. See `docs/coolify.md`. `NEXT_PUBLIC_APP_URL` is set explicitly in `docker-compose.yml` and `assertInternalOrigin()` (`lib/api/internal-origin.ts`) refuses to boot in production when it is unset, unparseable, or a different host from `APP_URL` — it still only warns elsewhere. It no longer guards self-fetches (there are none); it guards the GitHub App Manifest callback and the static-preview origins.

**Two working trees, two ports.** The primary checkout is `ai-genration-improvements` on
`http://localhost:3001`; `main` lives in the `.worktrees/main` git worktree on `http://localhost:3000`.
Both run at once, one dev server each. Per tree: code, `.next`, `generated/prisma`, `node_modules`.
Shared: Postgres, `public/uploads`, and every `AppSetting` row — so the same projects appear on both
ports, and data isolation would need a second database in that tree's `.env.local`. The `app.url`
setting row is deliberately empty so each server's own `APP_URL` / `NEXT_PUBLIC_APP_URL` decides its
origin; one row cannot describe two ports, and signed static-preview URLs plus the GitHub App
Manifest callback are built from it. Setup steps, the corepack invocation `pnpm` needs here, and why
a junctioned `node_modules` breaks Turbopack are in `single-dev-server.mdc`.

- **API auth gate** — `proxy.ts` denies every request under `/api` and `/preview-static` unless it matches `lib/auth/public-routes.ts` (`PUBLIC_API_ROUTES`). New routes are private by default. The gate is coarse: it decodes the Auth.js JWT for signature and expiry only, never touching Prisma. Membership, project ownership, ADMIN role, and the deactivated-user check (`getSessionUser` re-reads `isActive`; the `auth.ts` `jwt` callback strips a revoked token) stay in the routes — defence in depth, do not remove them. Denials are JSON 401 `{ error: { message, code, requestId } }`, never a redirect. Allowlist entries need an explicit path, explicit methods, a `reason`, and an `ownMechanism`; the Auth.js catch-all is listed action by action so `/api/auth/me` stays private. Guards: `tests/unit/api-route-auth.test.ts` (walks `app/api/**`, pins the public set, pushes every endpoint through the real proxy), `scripts/check-public-routes.ts` (verify step, rejects wildcards and prints the allowlist size), and the unauthenticated probe in `scripts/smoke-test.ts` (`SMOKE_AUTH_PROBE=off` to skip).
- **No self-fetch between routes** — an API route never calls a sibling route over HTTP on its own origin. The work lives in `lib/` and both the route and any internal caller call it directly — `lib/generation/analyze-edit-intent.ts` is the surviving example of the pattern. Routes stay as thin wrappers (authenticate, parse, call, map). The `internalCallHeaders` cookie relay is gone — do not reintroduce it. Failures are typed results, never a silent `if (response.ok)` else branch; inside a Job, record them with `recordJobStepFailure` (`lib/jobs/step-failure.ts`) so they reach the recovery panel and `/admin/jobs`.
- **Instance self-identity** — `lib/runtime/self.ts` `getSelfIdentity()` → `{ coolifyAppUuid, gitSha, instanceId, environment }`, cached per process. The only reader of `process.env.COOLIFY_APP_UUID`; Sentry restart, `/api/admin/health/rollback`, and `scripts/rollback.ts` all go through it and share `SELF_UUID_NOT_CONFIGURED`. Surfaced on `/admin/health`. Blank is the same as unset. App identity, not an integration credential — it does not belong in the Integration store.
- **Projects API** — `/api/projects`, Prisma `Project` (`lib/projects`)
- **Plan/Build** — `ProjectPhase` + `/api/projects/[id]/plan`; workspace chat modes `plan` | `build`. The plan is the first-build gate: the created project's arm (`sessionStorage` `navroop_arm_<projectId>`, written by `armProjectGeneration`, taken once by the workspace for that id only — never a global `navroopPrompt` / `targetUrl` / `autoStart`, which auto-started a paid build on the next project opened in the tab) is shown in chat during PLANNING and does not start generation; Approve (or skip-planning / URL import) starts the only first build. A URL import is not armed at all — it resumes from its own `ImportSource` row. A job that dies before any plan or site exists resumes to PLANNING (`resumablePhaseFromEvidence`); COMPLETE means a finished site (`lastCode` / checkpoint — not job `filesWritten`, which is stream progress). Stream complete is not enough to `succeedJob` / COMPLETE: `settleStreamedGeneration` (`lib/jobs/settle-generation.ts`) persists the streamed `<file>` blocks server-side (merged over the existing site, `NEED_IMAGE:` tokens resolved to real assets) and fails the job `no_files_generated` / `stack_mismatch` when nothing usable arrived. Recovery Try again starts a new billed build. `requestFollowUpPlan` still rolls a live site back to COMPLETE when the follow-up is discarded.

New projects default **NEXTJS**. PromptHero + pending-prompt (`navroop_pending_prompt`, the two heroes only — the template sheet keys its own `navroop_template_draft_<id>`) persist `{ text, stack, savedAt, designDirection, importMode, templateId }` (defaults NEXTJS + `minimal` + `reimagine`). A signed-out hero submit is handed to `AuthModal` in memory (`createSignedOutSubmit`) and spent once; leftover draft text never creates a project on a later sign-in.

Gallery `/templates`, PromptHero chips + Browse templates, workspace “Save as template” (private to the workspace). Create uses the normal plan/build path and increments `usageCount` atomically. Excludes `node_modules`, `.git`, `.env`, files over 10 MB. Filename `{slug}-{YYYY-MM-DD}.zip`. 5 exports/user/hour. Does not consume credits. - **URL import** — Prisma `ImportSource` + `lib/import/` (Playwright capture, WebP rehost, section segment, per-section generate). `createProject` skips planning for URL input. Modes `reimagine` (default) | `replicate`. Progress in chat. `POST /api/projects/[id]/import`. Workspace top bar shows the source URL. User-supplied URLs go through `lib/security/url-guard.ts` + `safeFetch` (SSRF: http(s) only, ports 80/443, DNS-checked private ranges, max 3 redirects, 10 MB). Imported HTML is stripped/wrapped in `lib/security/untrusted-html.ts` and stays in the user message. Coolify/Cloudflare/GitHub/Resend stay on raw `fetch`. Private-range rejects increment `AppSetting` `ssrf.privateRejects` and show on `/admin/usage`. Firecrawl markdown is a typed scrape (`lib/import/firecrawl.ts`): HTTP/network/credential failure is not an empty page — chat gets the English and `recordJobStepFailure` writes a `firecrawl` step. Playwright capture failure still aborts. One failed section continues; an empty `filesXml` is not a successful import. Pass `jobId` into `runProjectUrlImport` so the step is recorded. Hard capture/SSRF/empty-files aborts use `import_failed` (not `provider_error`); the SSE client reads `error.message` from `errorPayload` (never `String(error)`). A Firecrawl text miss is a chat warning on a succeeded job — do not put it on the generation RecoveryPanel. IMPORT Try again goes through `streamProjectImport`, not a generated build. `/admin/jobs` failed rows show `errorMessage` via `jobAdminFailureLine`.

CRUD ADMIN-only; members read-only. UI: `/settings/skills` and the Skills section in the workspace Brain tab. Usage table on `/admin/usage`. Distinct from always-on Brain memory.

Before that check, prompt edits kept stamping generations with the stale version, so output changes were never attributable.

Credits stay flat per action; admin cost is token-based (`lib/consumption/cost.ts`). Workspace spend ceiling (`monthlySpendLimitUsd` / `spendUsd`) auto-pauses at 100% (`pauseReason=SPEND_LIMIT`). Free is default (100 credits); Pro is seeded inactive. Templates in `lib/email/templates/` (English). Never throw on the request path. Observability/security alerts use `emailClass: 'security'` so they are not dropped by the per-workspace limit.
- **Password change / reset** — Prisma `PasswordResetToken` (sha256 `tokenHash` only). `lib/password-reset/`, `POST /api/auth/forgot-password` (generic success, 3/email/hr + 10/IP/hr), `GET /reset-password`, `POST /api/auth/reset-password`. AuthModal “Forgot password?”. ADMIN `POST /api/admin/team/[id]/reset-link` + Team “Send reset link”. Successful reset marks the token used. Every new password — reset **and** Settings → Password (`changePassword`) — goes through `passwordChangeWrites` (`lib/auth/session-invalidation.ts`): one transaction that writes the hash, stamps `User.passwordChangedAt` and drops `Session` rows, so JWTs issued earlier are rejected. The stamp is truncated to a whole second because `auth.ts` compares it against `token.iat` (whole seconds) with `>`; the Settings page re-signs the current tab in with the new password so the person changing it is not signed out of their own change. Both password mails are `emailClass: 'security'`.
- **Persistent volume** — Coolify mount `/data` (`DATA_DIR`, default `/data`). Cache and bootstrap only: `config/observability.json` (rebuilt from Sentry Integration), `cache/` (GitHub tokens, provider health, thumbnail derivatives), `tmp/` (swept hourly). Volume id in `/data/.volume-id` + `AppSetting` `runtime.volumeId`. Not in DB backup; reconstructible. `lib/runtime/data-dir.ts` `ensureDataDir()` at boot. `DataDirStatus.checked` is false until that probe runs — "not checked yet" is not a missing volume, and `error` stays null. `describeDataDir()` (`lib/health/check.ts`) maps it to `state: 'ok' | 'not_checked' | 'unwritable'` plus plain English, surfaced on `/api/health`, `/api/admin/health`, and `/admin/health`. - **Error tracking** — Sentry (`@sentry/nextjs`) via Prisma `Integration` kind `SENTRY` + runtime file `OBSERVABILITY_CONFIG_PATH` (default `/data/config/observability.json` on the `/data` volume). SDK inits from that file in `instrumentation.ts` before the DB is up; connect/disconnect rewrites the file and needs an app restart. `persistSentryConnection` / `persistSentrySettings` / `disconnectSentry` / boot `reconcileRuntimeConfig` are the only writers — one writer per derived file, so `migrateEnvSentry` does not write it. ADMIN `/admin/integrations` (fourth card: paste DSN or OAuth). Auth token stays in Integration secrets — not the runtime file. Quota/heartbeat/issue checks skip (recorded, not a silent pass) when there is no auth token (limited). First boot migrates leftover `SENTRY_DSN` to "Sentry (migrated)" then ignores the env var. Locally, no integration = skip init, no warning spam. `lib/logger`, `lib/sentry`, `lib/request-id`, `GET /api/health`, ADMIN `/admin/health`. Prisma `ObservabilityCheck` + `CronRun`.
- **Jobs** — Prisma `Job` (`@@map("GenerationJob")`) + `lib/jobs/`. Kinds: PLAN/BUILD/FOLLOWUP/IMPORT/AUDIT/PUBLISH/DOMAIN_VERIFY/EXPORT/TEMPLATE_THUMBNAIL. Heartbeat 10s; stale after 60s. `listReconcileCandidates` uses `COALESCE("heartbeatAt", "createdAt")` — a null heartbeat is not already stale. `succeedJob` / `failJob` / `abandonJob` / `cancelJob` write through `updateJobIfActive` (`WHERE status IN ('QUEUED', 'RUNNING')` on the same UPDATE). A lost write is the UPDATE row count (`commitActiveJob` returns null; `abandonActiveJob` returns `{ wrote }`) — never a re-read of the row's status — so only the winning writer runs phase/lock/compensation; settling twice is a no-op and a `finally` can always call `ensureJobSettled` (`lib/jobs/settle.ts`) as the last-resort terminal write. `beginJobHeartbeat(jobId, { signal })` stops itself on abort and when the row leaves QUEUED/RUNNING — a live heartbeat hides a job from the staleness reaper, so any route that streams to a client must pass `request.signal` or an orphaned job survives to the 20 min timeout with the chat input locked. Boot reconcile in `instrumentation.ts` + `POST /api/cron/reap-jobs` every minute. 20 min timeout even with a fresh heartbeat. Publish is a job: steps + `resourceIds` persist after each step; UI polls the job. First-time publish abandon compensates Coolify/DNS and archives the repo; re-publish abandon rolls back nothing. Orphan cron `POST /api/cron/cleanup-orphans` (daily). Recovery panel: `recoveryHeading(kind)` (an import failure says the import did not finish). Chat shows it only for PLAN, BUILD, FOLLOWUP, and IMPORT (`showsChatRecovery`); publish keeps its own sheet; audit, domain-verify, export, and thumbnail stay out. IMPORT Try again retries the recorded URL and mode through `streamProjectImport` → `POST /api/projects/[id]/import` (`recoveryRetryIntent`); it is hidden when `offersRecoveryRetry` is false (blocked page, SSRF/private URL, unresolved host, plus credits/no-provider) and `recoveryNextStepLine` says what to do instead. `offersRecoveryKeep` is false for IMPORT — `filesWritten` is generation progress. Chat busy/building follows the latest job (QUEUED/RUNNING only) — ABANDONED/FAILED/CANCELLED unlocks the input even if `Project.phase` is still BUILDING. Credits charged once at RUNNING (`creditsChargedAt`). Job rows also store `tokensIn` / `tokensOut` / `estimatedCostUsd` / `provider` / `model` / `queuePosition`. Generate keys come from `getEffectiveApiKey` (personal → org / admin panel → env); a rejected key does not fall back to the same vendor's env key. **Both plan and build resolve providers through `loadEffectiveProviderEnv` (lib/ai/effective-env.ts)** — plan does it in `defaultCompletePlan` (lib/projects/plan.ts) and both build clients through the shared `clientForEntry` (lib/ai/client-for-entry.ts); the plan path once read `process.env` alone, so an admin-UI-only deployment could build but never create a project. The overlay also carries `AI_PRIMARY_PROVIDER` / `AI_PRIMARY_MODEL` from the admin settings `ai.primaryProvider` / `ai.primaryModel`, and a requested model is **explicit-only**: neither plan nor the generate route defaults it to `appConfig.ai.defaultModel` (that default outranked the configured primary on every call); the workspace client sends an empty model unless the user picked one (pinned by `tests/unit/generate-provider-preflight.test.ts`). Provider failover + in-process 429 queue live in `lib/ai/`: `loadProviderChain` skips keyless providers; plan uses `completeWithProviderFailover` and generate uses `executeWithCompletionFailover` (same `shouldFailover`). Fail over immediately on auth (401/403, including unregistered-caller / identity), not-found (404-model), quota (429/quota text), unavailable (5xx, network, timeout), and empty completion — not on content-policy / request-fault 4xx. Stream `onError` is captured (`bindStreamErrorCapture`) because AI SDK `textStream` drops error parts — `attach` must `defineProperty` the `streamError` getter, since `Object.assign` would copy the value it returned and pin it to `undefined`. ## Do not

- Dump `omni-*` / `gstack-*` / Coolify / WHM skill trees into this repo (still available from `~/.cursor/skills/`)
- Touch Next.js version or unrelated runtime unless asked

- Interpolate a composed `Prisma.sql` / `Prisma.join` / `Prisma.raw` fragment into a `` prisma.$queryRaw`…` `` / `` $executeRaw`…` `` tagged template. It works under plain Node (so Vitest passes) but binds the fragment as a parameter inside the bundled Next server, producing `SET $1` and Postgres 42601 — that is what silently killed every job heartbeat. Build the SQL text and number the placeholders yourself, then use `$queryRawUnsafe` / `$executeRawUnsafe` (column names from source literals only, values always bound). Guard: `tests/unit/raw-sql-composition.test.ts`.
- Let a `'use client'` file reach a Node-only builtin or a server-only module (Prisma, `lib/db`, `lib/logger`, `lib/security/url-guard`, an admin `load-admin`). Turbopack then puts `node:async_hooks` / `node:dns` in the browser graph and the route 500s on a cold compile — `next dev` stays up, so the page looks fine until someone loads it cold. Keep user-facing copy in a client-safe sibling (`lib/security/url-guard-messages.ts`, `lib/import/error-messages.ts`) and give client components their own serialisable prop types instead of importing the loader for its types. Guard: `tests/unit/client-import-boundary.test.ts` walks value imports from every client file, stops at `'use server'`, and still fails a type-only import of a denylisted server module. Neither `tsc` nor Vitest sees this class otherwise — only `next build` or a cold dev compile.
- Create throwaway `.ts` / `.tsx` files at the repo root. `tsconfig` `include` is `**/*.ts`, so a scratch file there fails `tsc --noEmit` with TS6053 (or worse, typechecks as app code).
- Run a second `vitest --coverage` in this checkout while another is in flight. Both write `coverage/.tmp` and the later run (or the coverage table) is garbage.
