# Agent guide — Navroop / Open Lovable

Navroop is an invite-only admin shell around Open Lovable (Next.js App Router, React 19, Tailwind, Prisma/Postgres, Firecrawl). Brand the product as Navroop. Default theme is light. Do not revert studio/admin chrome. Generation runs in the background via `GenerationProvider`.

**MCP.** Both files declare one HTTP server, `dev3000` on `http://localhost:3684/mcp`. It is an
external dev tool that has to be running already: nothing in this repository starts it, it is not
a dependency, and every call fails harmlessly when it is absent. Claude Code enables it through
`enabledMcpjsonServers` in the gitignored `.claude/settings.local.json`, so the enablement is not
reviewable from the repo — if that surprises you, that is the finding. The two files are duplicates
with no generator: edit one, edit the other.

**Specs.** `docs/superpowers/specs/` holds dated design specs produced by the `brainstorming` and
`writing-plans` skills — currently one, `2026-08-19-interactive-generation-ux-design.md`, which is
the only written record of the post-sandbox preview architecture. A spec is design history, not a
map: once its decisions are load-bearing they belong in the Product map below, and the spec stays
as the reasoning behind them.

After meaningful product/schema/API/layout changes, update this file and the `.cursor` docs in the
same session (`keep-cursor-current.mdc`). Use **pnpm**, not npm — keep `pnpm-lock.yaml`; do not
create `package-lock.json`.

## Product map

Authenticated app chrome: `components/layout/Sidebar` + studio shell. Generation is backgrounded via `GenerationProvider`. **One Next.js server per checkout, on that checkout's assigned port** (this tree `:3001`, `.worktrees/main` `:3000` — table in `single-dev-server.mdc`) — only the dedicated **dev server** agent may start/restart it, run `prisma generate`, or replace locked Next/Prisma binaries. Coolify production is `docker-compose.yml` (`app` + `postgres`); local Postgres on host `5433` is `docker-compose.dev.yml`. See `docs/coolify.md`. `NEXT_PUBLIC_APP_URL` is set explicitly in `docker-compose.yml` and `assertInternalOrigin()` (`lib/api/internal-origin.ts`) refuses to boot in production when it is unset, unparseable, or a different host from `APP_URL` — it still only warns elsewhere. It no longer guards self-fetches (there are none); it guards the GitHub App Manifest callback and the static-preview origins.

**Two working trees, two ports.** The primary checkout is `ai-genration-improvements` on
`http://localhost:3001`; `main` lives in the `.worktrees/main` git worktree on `http://localhost:3000`.
Both run at once, one dev server each. Per tree: code, `.next`, `generated/prisma`, `node_modules`.
Shared: Postgres, `public/uploads`, and every `AppSetting` row — so the same projects appear on both
ports, and data isolation would need a second database in that tree's `.env.local`. The `app.url`
setting row is deliberately empty so each server's own `APP_URL` / `NEXT_PUBLIC_APP_URL` decides its
origin; one row cannot describe two ports, and signed static-preview URLs plus the GitHub App
Manifest callback are built from it. Setup steps, the corepack invocation `pnpm` needs here, and why
a junctioned `node_modules` breaks Turbopack are in `single-dev-server.mdc`.

- **API auth gate** — `proxy.ts` denies every request under `/api` and `/preview-static` unless it matches `lib/auth/public-routes.ts` (`PUBLIC_API_ROUTES`). New routes are private by default. The gate is coarse: it decodes the Auth.js JWT for signature and expiry only, never touching Prisma. Membership, project ownership, ADMIN role, and the deactivated-user check (`getSessionUser` re-reads `isActive`; the `auth.ts` `jwt` callback strips a revoked token) stay in the routes — defence in depth, do not remove them. Denials are JSON 401 `{ error: { message, code, requestId } }`, never a redirect. Allowlist entries need an explicit path, explicit methods, a `reason`, and an `ownMechanism`; the Auth.js catch-all is listed action by action so `/api/auth/me` stays private. Guards: `tests/unit/api-route-auth.test.ts` (walks `app/api/**`, pins the public set, pushes every endpoint through the real proxy), `scripts/check-public-routes.ts` (verify step, rejects wildcards and prints the allowlist size), and the unauthenticated probe in `scripts/smoke-test.ts` (`SMOKE_AUTH_PROBE=off` to skip). **Cross-origin writes** — the same gate refuses a state-changing request that carries the session cookie and did not come from this app: `Origin` must resolve to the request's own `Host`/`X-Forwarded-Host`, and `Sec-Fetch-Site` may not be `cross-site` or `same-site` (the preview hostname is a sibling site serving generated scripts). Policy in `lib/auth/csrf.ts`, `ORIGIN_CHECK_EXEMPT` is empty and the sweep in `tests/unit/mutating-route-authz.test.ts` refuses an exemption that is not declared. Server Actions are untouched — Next does the same Origin/Host comparison for them (F-350).
- **No self-fetch between routes** — an API route never calls a sibling route over HTTP on its own origin. The work lives in `lib/` and both the route and any internal caller call it directly — `lib/generation/analyze-edit-intent.ts` is the surviving example of the pattern. Routes stay as thin wrappers (authenticate, parse, call, map). The `internalCallHeaders` cookie relay is gone — do not reintroduce it. Failures are typed results, never a silent `if (response.ok)` else branch; inside a Job, record them with `recordJobStepFailure` (`lib/jobs/step-failure.ts`) so they reach the recovery panel and `/admin/jobs`.
- **Instance self-identity** — `lib/runtime/self.ts` `getSelfIdentity()` → `{ coolifyAppUuid, gitSha, instanceId, environment }`, cached per process. The only reader of `process.env.COOLIFY_APP_UUID`; Sentry restart, `/api/admin/health/rollback`, and `scripts/rollback.ts` all go through it and share `SELF_UUID_NOT_CONFIGURED`. Surfaced on `/admin/health`. Blank is the same as unset. App identity, not an integration credential — it does not belong in the Integration store.
- **Projects API** — `/api/projects`, Prisma `Project` (`lib/projects`). The rest of the per-project surface, so the map is the inventory: `POST /api/projects/[id]/duplicate` (copies the site into a new project, dashboard-card shape back), `POST /api/projects/[id]/restore` (undo a soft delete), `GET /api/projects/[id]/files` (the current files, from `lastCode` — readable by any signed-in member, writes stay owner-gated), `POST /api/projects/[id]/lock/release` (force-release a held lock), `POST /api/projects/[id]/quality-signals` (thumbs up/down → `recordThumbs`). `tests/unit/docs-accuracy.test.ts` fails when a route under `app/api/projects/[id]/` is not named somewhere in this file.
- **Plan/Build** — `ProjectPhase` + `/api/projects/[id]/plan` (`POST /api/projects/[id]/plan/approve` starts the one first build, `POST /api/projects/[id]/plan/refine` re-plans from a new prompt, `POST /api/projects/[id]/plan/followup` plans a change to a finished site — all three in `lib/projects/plan.ts`); workspace chat modes `plan` | `build`. The plan is the first-build gate: the created project's arm (`sessionStorage` `navroop_arm_<projectId>`, written by `armProjectGeneration`, taken once by the workspace for that id only — never a global `navroopPrompt` / `targetUrl` / `autoStart`, which auto-started a paid build on the next project opened in the tab) is shown in chat during PLANNING and does not start generation; Approve (or skip-planning / URL import) starts the only first build. A URL import is not armed at all — it resumes from its own `ImportSource` row. A job that dies before any plan or site exists resumes to PLANNING (`resumablePhaseFromEvidence`); COMPLETE means a finished site (`lastCode` / checkpoint — not job `filesWritten`, which is stream progress). Stream complete is not enough to `succeedJob` / COMPLETE: `settleStreamedGeneration` (`lib/jobs/settle-generation.ts`) persists the streamed `<file>` blocks server-side (merged over the existing site, `NEED_IMAGE:` tokens resolved to real assets) and fails the job `no_files_generated` / `stack_mismatch` when nothing usable arrived. Recovery Try again starts a new billed build. `requestFollowUpPlan` still rolls a live site back to COMPLETE when the follow-up is discarded.
- **Stacks** — Prisma `Stack` + `lib/stacks` — exactly three: **Next.js (App Router), React (Vite), static HTML**. There is no Astro, Vue or Svelte stack: the enum in `prisma/schema.prisma`, the switch in `lib/stacks/routes.ts` and the PromptHero picker all know three, and this line claimed six until 2026-08-19. `playwright.config.ts` had a project per invented name, each running a `.fixme()` spec, so the report showed six stacks' worth of coverage for one skip. New projects default **NEXTJS**. PromptHero + pending-prompt (`navroop_pending_prompt`, the two heroes only — the template sheet keys its own `navroop_template_draft_<id>`) persist `{ text, stack, savedAt, designDirection, importMode, templateId }` (defaults NEXTJS + `minimal` + `reimagine`). A signed-out hero submit is handed to `AuthModal` in memory (`createSignedOutSubmit`) and spent once; leftover draft text never creates a project on a later sign-in.
- **Templates** — Prisma `Template` + `lib/templates/`. Ten built-in briefs (`prisma/seed-templates.ts`, Indian-context placeholders). Gallery `/templates`, PromptHero chips + Browse templates, workspace “Save as template” (private to the workspace). Create uses the normal plan/build path and increments `usageCount` atomically. Plan project-count limit still applies. ADMIN `/admin/templates` (CRUD, reorder, Test, Generate thumbnails). List is built-in (`workspaceId` null) plus this workspace; never leak another workspace. `'use server'` `lib/templates/actions.ts` exports only async actions; row mapper `toPublic` lives in `lib/templates/public.ts`.
- **ZIP export** — `GET /api/projects/[id]/export` streams a zip from the latest (or `?checkpointId=`) Checkpoint snapshot via `archiver`. README includes stack install/dev/build from `lib/stacks`. Excludes `node_modules`, `.git`, `.env`, files over 10 MB. Filename `{slug}-{YYYY-MM-DD}.zip`. 5 exports/user/hour. Does not consume credits. UI: workspace overflow **Download code** + Version history.

Last-admin trigger + atomic credit consume + Deployment ON DELETE RESTRICT.
- **Visual Edits** — `lib/visual-edits` + workspace preview toolbar. Inspector is also injected into static preview HTML at upload time (`lib/preview/inject.ts`).
- **Static preview** — `GET /api/projects/[id]/preview` reports status and mints the signed URL, `POST` the same path rebuilds (`lib/preview/{status,url,token}.ts`). Prisma `PreviewBuild` + `Project.previewMode` (single member `STATIC`) / `activePreviewBuildId`. `lib/preview/build.ts` builds the served snapshot **in-process with esbuild** — `buildStaticSite` (`lib/preview/server-bundle.ts`) is the server-side twin of the in-browser bundler (same esbuild, same virtual filesystem, same esm.sh import map), so what a user approves in the preview is what gets stored. No VM is involved. Served **only from a distinct preview origin** — `preview-static.{zone}` when Cloudflare is connected, else the `preview.host` setting (Admin → Configuration, group Application; env fallback `PREVIEW_STATIC_HOST`, runtime) — at `/preview-static/{projectId}/…` with a 2-hour signed URL token, not a cookie. `previewStaticBaseUrl` never falls back to the app origin (F-140): with neither configured no preview URL is minted, Open-in-new-tab disables with a connect hint, and the in-browser preview keeps working. Caps: 200 MB / 5,000 files (`PREVIEW_TOO_LARGE`). Retention: active + 2 recent + bookmarked (daily thin-checkpoints). Preview mode and Coolify deploy mode are independent. One generation produces one preview capture (`capturePreviewAfterGeneration` keyed by project + checkpoint); a newer checkpoint still captures. `activePreviewBuildId` is adopted only if the incoming build is newer (`createdAt`), so a stale overlapping capture cannot overwrite. After apply, `persistProjectGeneration` may return `previewNotice`; `generation-runtime` surfaces it in chat (`surfacePreviewNotice`) so a failed preview is not described as a failed build, and the same sentence is not added twice if `saveCurrentProject` also persists.
- **Connectors / GitHub** — `/connectors`, `/api/github`, Prisma `GitHubConnection`. The push signs with a **per-user** OAuth token, so a rejection is recorded per user: `GitHubConnection.lastError` / `lastErrorAt` (`lib/github/connection-error.ts`, raw SQL) and shown on that member's `/connectors` card. It must **never** be written to the workspace `GITHUB_DEPLOY` Integration — that row holds the GitHub App credentials publish uses, `missingIntegrationKinds` counts only CONNECTED, and flipping it to ERROR blocked publishing workspace-wide over one member's expired grant and told an admin to reconnect an App that was never broken (F-206; same rule as F-212 — an integration's status may only be written by a check that exercised its own credentials). A note counts only while `lastErrorAt > connectedAt`, so a reconnect retires it with no second write; a successful push clears it outright.
- **Checkpoints** — `/api/projects/[id]/checkpoints`, Prisma `Checkpoint`; `POST /api/projects/[id]/checkpoints/[checkpointId]/preview` enters a read-only view of an older version, `POST /api/projects/[id]/checkpoints/exit` leaves it, `POST /api/projects/[id]/checkpoints/[checkpointId]/restore` makes it current, and `POST /api/projects/[id]/checkpoints/[checkpointId]/bookmark` toggles the flag retention honours (`lib/checkpoints/actions.ts`). The latest checkpoint is the source of truth for publish and ZIP export. `readSnapshot` (`lib/checkpoints/snapshot-store.ts`) throws `SnapshotReadError` when storage or gunzip fails — an empty array means the checkpoint is genuinely empty, never "could not read". Callers (checkpoint restore, `collectPublishFiles`, ZIP export) must not catch that and fall through to `project.lastCode`. **A preview is a read.** It writes `Project.previewingCheckpointId` (`lib/checkpoints/preview-state.ts`) and nothing else; `lib/checkpoints/served-files.ts` answers `GET /api/projects/[id]/files` from that checkpoint's snapshot, so `lastCode` — what publish, ZIP export and the next generation read — is never rewritten to show an old version. `previewCheckpoint` used to write the snapshot straight into `lastCode` with "this is temporary" held only in a `useState`, so one reload left the project silently _being_ the old version (F-102). Do not reintroduce a write there: the flag is a column precisely so a reload can restore the banner (`getCheckpoints` returns `previewingCheckpointId`; the workspace must not shadow it with local state), and the read path reports a pruned, missing or unreadable previewed snapshot as an error rather than quietly serving the live files under a "viewing v3" banner. The preview flag write still takes the owner gate and the project lock, and its answer is the UPDATE row count — a database missing the column (an environment behind its own migrations) is a 503 naming the missing update, never a 500 and never a success.
- **Preview and bundling (in the browser)** — `components/workspace/BrowserPreview.tsx` renders a generated project entirely in the browser: `esbuild-wasm` bundles the project files, runtime dependencies resolve to pinned esm.sh URLs (`lib/preview/deps.ts` — React 19), and the result runs in a sandboxed iframe. No VM, no dev server, no network round trip. The wasm binary is copied from `node_modules` into `public/preview-vendor/` (gitignored) by `scripts/copy-preview-vendor.mjs`, which runs ahead of `next dev` / `next build` (`package.json` scripts), and `next.config.ts` keeps `esbuild` in `serverExternalPackages` for the server-side twin. The sandbox VM subsystem — `lib/sandbox/`, `SandboxProviderConfig`, the e2b/modal/daytona drivers, `/api/projects/[id]/sandbox`, `/admin/sandbox-providers`, and the `reap-sandboxes` / `check-sandbox-providers` crons — was deleted in migration `20260819010000_drop_sandbox_columns`; `lib/workspace/sandbox-request.ts` is the single gate that keeps the remaining workspace branches unreachable. Design history: `docs/superpowers/specs/2026-08-19-interactive-generation-ux-design.md`. What happens to generated code before it is stored: `docs/build-autofix.md`.
- **Assets** — Prisma `ProjectAsset` + `lib/assets` + `lib/storage`; workspace Assets tab; `/api/projects/[id]/assets`, with `PATCH`/`DELETE /api/projects/[id]/assets/[assetId]` for alt text and removal. `STORAGE_DRIVER=local|s3` (ElasticLake: `ELK_*`, `forcePathStyle: true`), `NEED_IMAGE:` intercept. `s3Get` / `s3Exists` / `localExists` rethrow anything that is not not-found (`isObjectNotFoundError`; local also treats `ENOENT`/`ENOTDIR` as absent) — a permission or network miss is not "missing". **A `NEED_IMAGE:` token is generated first, then falls back to stock, in this precedence** (`lib/assets/fulfill.ts`): (1) the **image worker** — a self-hosted Cloudflare-style endpoint from `tooling.images.workerUrl` / `.token` / `.model` (env `IMAGE_WORKER_URL` / `IMAGE_WORKER_TOKEN` / `IMAGE_WORKER_MODEL`, default model `lucid-origin`, ~12s per image, three concurrent), free and metered by nothing because it is the operator's own endpoint, with `rewriteSubject` stripping text the model would try to draw (`lib/assets/image-worker.ts`); (2) **OpenAI `gpt-image-1`**, then (3) **Google Imagen 3** — both real spend, so they check and consume credits and are only reached with no worker configured; then, serially, (4) **Unsplash** when `tooling.unsplash.accessKey` is set (`lib/assets/stock-photo.ts`) and (5) **Openverse**, which needs **no key at all** and is restricted to CC0 / public-domain results because a generated site is handed to its owner and no attribution caption is guaranteed to survive (`lib/assets/openverse.ts`). Openverse is why a deployment with no photo provider configured still ships real photographs; Unsplash's demo tier is 50 requests/hour, which one multi-page build can exhaust. A token no provider could fill is reported as `unfulfilled`, not silently placeholdered.
- **URL import** — Prisma `ImportSource` + `lib/import/` (Playwright capture, WebP rehost, section segment, per-section generate). `createProject` skips planning for URL input. Modes `reimagine` (default) | `replicate`. Progress in chat. `POST /api/projects/[id]/import`. Workspace top bar shows the source URL. User-supplied URLs go through `lib/security/url-guard.ts` + `safeFetch` (SSRF: http(s) only, ports 80/443, DNS-checked private ranges, max 3 redirects, 10 MB). Imported HTML is stripped/wrapped in `lib/security/untrusted-html.ts` and stays in the user message. Coolify/Cloudflare/GitHub/Resend stay on raw `fetch`. Private-range rejects increment `AppSetting` `ssrf.privateRejects` and show on `/admin/usage`. Firecrawl markdown is a typed scrape (`lib/import/firecrawl.ts`): HTTP/network/credential failure is not an empty page — chat gets the English and `recordJobStepFailure` writes a `firecrawl` step. Playwright capture failure still aborts. One failed section continues; an empty `filesXml` is not a successful import. Pass `jobId` into `runProjectUrlImport` so the step is recorded. Hard capture/SSRF/empty-files aborts use `import_failed` (not `provider_error`); the SSE client reads `error.message` from `errorPayload` (never `String(error)`). A Firecrawl text miss is a chat warning on a succeeded job — do not put it on the generation RecoveryPanel. IMPORT Try again goes through `streamProjectImport`, not a generated build. `/admin/jobs` failed rows show `errorMessage` via `jobAdminFailureLine`.
- **Skills** — Prisma `Skill` (workspace-scoped, no projectId). Conditional instruction sets matched per message (`lib/skills/`, max 2). Injected AFTER the cacheable prefix, never inside it. CRUD ADMIN-only; members read-only. UI: `/settings/skills` and the Skills section in the workspace Brain tab. Usage table on `/admin/usage`. Distinct from always-on Brain memory.
- **Brain memory** — Prisma `MemoryEntry` + `AppSetting.memoryExtractionEnabled` (default true). Workspace + project durable context in `lib/memory/`. Injected INSIDE the cacheable prefix (`buildMemoryBlock`) on the chat, plan AND URL-import paths (`runProjectUrlImport` loads it once and threads it through `buildImportStablePrefix`). Manual = ACTIVE; extracted = PENDING until approved. Token cap ~1500, with project memory given first refusal on half of it so a full workspace budget cannot drop it; `truncatedScopes` names the scope the Brain footer warns about. Each entry renders as exactly one flattened bullet, so stored content cannot forge prompt structure. ADMIN toggle on `/admin/usage`.
- **Quality signals** — Prisma `QualitySignal` + `PromptVersion`, `lib/signals/`, `lib/prompts/version.ts`. Collectors swallow errors. ADMIN `/admin/quality`. No self-grading AI signal. Verified by reading pnpm 11.21.0's own bundle (corepack `pnpm/11.21.0/dist/pnpm.mjs`): the `run` handler and the `exec` handler gate it with the same `if (opts.verifyDepsBeforeRun) await runDepsStatusCheck(opts)`, so `false` skips it for **`pnpm exec` as well as `pnpm run`**. It narrows the hazard on both; it does not close it. The purge lives inside `pnpm install` itself (`purgeModulesDirsOfImporters` — no TTY throws `ABORTED_REMOVE_MODULES_DIR_NO_TTY`, a TTY prompts "will be removed and reinstalled from scratch", and `confirmModulesPurge && !ci` means `CI=true` purges with no prompt), so an explicit `pnpm install` is untouched by the flag; and the flag is one file away — `pnpm_config_verify_deps_before_run` in the environment overrides it, and a CI image or a checkout without this `pnpm-workspace.yaml` gets the default. The direct-binary convention costs nothing, does not depend on a setting, and is what the hooks already do. Tests use `TEST_DATABASE_URL` (`openlovable_test` on 5433) — never the app database. Unit-test `fetch` to loopback is blocked unless the test calls `allowLocalhost('reason')` (`tests/setup/network-guard.ts`). `pnpm db:test` creates the databases **and** migrates the test one (`scripts/migrate-test-db.ts`, also `pnpm db:test:migrate`); it runs `prisma migrate deploy`, never `prisma generate`, and refuses to run unless the target database is named exactly `openlovable_test`. Without that step `openlovable_test` drifts behind the committed schema and raw-SQL suites pass while proving nothing. Coverage floors are a ratchet set just under the measured total. **The numbers live in `vitest.config.ts` (`thresholds`) and nowhere else** — each carries its measurement date in a comment beside it, and three documents once stated three different, all-wrong quadruples while all three told the reader to raise them, so a contributor raising the floor they had read was raising it from a number the config did not hold. Raise, never lower. Functions is the volatile column (v8 enumerates every function in an imported module), so its floor sits furthest under the observed range. Only one `vitest --coverage` may run in a checkout — concurrent runs corrupt `coverage/.tmp`. The repo-write guard (`tests/setup/repo-write-guard.global.ts`) runs as Vitest `globalSetup` and fails the suite if a test wrote gitignored state (`.data`, `public/uploads`, `tmp/backups`). Schema drift uses a disposable `openlovable_shadow` (`SHADOW_DATABASE_URL`, derived from the test host; never `DATABASE_URL` or `TEST_DATABASE_URL`). CI: `.github/workflows/verify.yml` + nightly `verify:full`. Rollback: `scripts/rollback.ts` / `/admin/health` (type `roll back`); DB is not auto-reverted. Runbook: `docs/release.md`.

## Do not

- Commit or overwrite `.env.local`
- Dump `omni-*` / `gstack-*` / Coolify / WHM skill trees into this repo (still available from `~/.cursor/skills/`)
- Touch Next.js version or unrelated runtime unless asked
- Export a sync function from a `'use server'` file (Next treats every export as a Server Action and they must be async). Keep mappers in a sibling module without `'use server'`.
- Interpolate a composed `Prisma.sql` / `Prisma.join` / `Prisma.raw` fragment into a `` prisma.$queryRaw`…` `` / `` $executeRaw`…` `` tagged template. It works under plain Node (so Vitest passes) but binds the fragment as a parameter inside the bundled Next server, producing `SET $1` and Postgres 42601 — that is what silently killed every job heartbeat. Build the SQL text and number the placeholders yourself, then use `$queryRawUnsafe` / `$executeRawUnsafe` (column names from source literals only, values always bound). Guard: `tests/unit/raw-sql-composition.test.ts`.
- Let a `'use client'` file reach a Node-only builtin or a server-only module (Prisma, `lib/db`, `lib/logger`, `lib/security/url-guard`, an admin `load-admin`). Turbopack then puts `node:async_hooks` / `node:dns` in the browser graph and the route 500s on a cold compile — `next dev` stays up, so the page looks fine until someone loads it cold. Keep user-facing copy in a client-safe sibling (`lib/security/url-guard-messages.ts`, `lib/import/error-messages.ts`) and give client components their own serialisable prop types instead of importing the loader for its types. Guard: `tests/unit/client-import-boundary.test.ts` walks value imports from every client file, stops at `'use server'`, and still fails a type-only import of a denylisted server module. Neither `tsc` nor Vitest sees this class otherwise — only `next build` or a cold dev compile.
- Create throwaway `.ts` / `.tsx` files at the repo root. `tsconfig` `include` is `**/*.ts`, so a scratch file there fails `tsc --noEmit` with TS6053 (or worse, typechecks as app code).
- Run a second `vitest --coverage` in this checkout while another is in flight. Both write `coverage/.tmp` and the later run (or the coverage table) is garbage.
